# 画境 · AI 影像工作台

基于 ComfyUI 的本地图片与视频创作界面。不用碰节点，打开就能出图、出视频。

技术栈：Tauri 2 + Vue 3 + Vite + TypeScript。后端直接调用本机 ComfyUI 的 HTTP / WebSocket 接口。

---

## 快速开始

**方式一：安装包（推荐）**

双击 `画境_1.1.1_x64-setup.exe` 装好，从开始菜单启动。

**方式二：免安装**

直接运行 `src-tauri\target\release\huajing.exe`。

启动后如果顶栏显示「ComfyUI 未运行」，点一下旁边的「启动 ComfyUI」按钮，
它会用你原有的参数（`--lowvram --use-sage-attention` 那一套）把后端拉起来，
冷启动约 30–60 秒。生成时如果后端没开，应用也会自动帮你启动。

## 六个功能

| 页面 | 做什么 | 用什么模型 | 大致耗时 |
|---|---|---|---|
| 文生图 | 只写提示词，从零出图 | Qwen-Image 2.1 / Z-Image Turbo 可切 | 50–90 秒 / 8–15 秒 |
| 单图编辑 | 上传一张图，改衣服、换背景、调风格 | Qwen-Image 2.1 | 25–50 秒 |
| 多参考图 | 最多 6 张图组合（人物 + 服装 + 场景） | Qwen-Image 2.1 + KV 缓存 | 50–150 秒 |
| 多参考图 + 2K | 多图组合出图后自动做 2K 精修放大 | 上面两套串起来 | 2–4 分钟 |
| 2K 放大 | 任意图片放大 2 倍并补细节 | Z-Image + RealESRGAN | 15–60 秒 |
| 帧生视频 | 首帧或首尾帧生成带声音的视频 | MiniMax H3 Turbo（本地） | 依时长与显存而定 |

耗时是 4060 Laptop 8G 上的实测值，会随尺寸和参考图数量变化。

另外有三样贯穿全局的能力：**提示词优化**（接 DeepSeek）、**画面标注**（在图上画圈指位置）、
**隐私空间**（加密存储）。见下面各自的章节。

## 写提示词的三个便利设计

### 1. 引用标签点一下就好

多参考图/单图编辑模式里，提示词框下面会出现一排缩略图 chip，
每个对应一张参考图。**点一下就插到光标位置**，不用手打 `<image1>`。

标签编号按「实际送进模型的顺序」来 —— 中间留空的槽位会被跳过、后面的图往前顶，
chip 上的编号和这个顺序一致，不会对不上。

### 1.5 种子的默认行为

**默认每次生成都换随机种子。** 只有你明确要求「固定」时才固定：

- 高级参数里的「随机 / 固定」开关
- 或者历史记录的「参数复现」—— 它为了能复现会把种子固定下来

固定状态会**明确显示在生成按钮上方**，并带一个「切回随机」按钮。这是必要的：
种子开关在默认折叠的「高级参数」里，不定个提示，很容易在改完提示词之后还一直复用
同一个种子 —— 而同一个种子配不同提示词很容易出噪点。

### 2. 一键优化提示词（DeepSeek）

提示词框右上角有「优化提示词」。它把提示词连同本地的 Qwen-Image 2.1 提示词规范
（`src-tauri/prompts/qwen-guide.md`，是本地 skill 的副本）一起交给 DeepSeek 改写。

- 结果**直接替换**输入框，旁边出现「恢复原文」，点一下回到优化前
- 如果参考图上有标注，会额外告诉模型「标记只负责指位置」，避免它去臆测标记内容
- 各模式的改写策略不同：文生图要求写完整句子，编辑模式强制套用
  「改什么 + 改成什么 + 什么保持不变」，2K 精修则要求**不要引入新内容**

配置在「设置 → DeepSeek」：填 API Key → 点「获取模型列表」→ 从下拉框选模型。

**模型名不写死**，是调 `/v1/models` 实时探测的，DeepSeek 换模型名不用改应用。

不想把 Key 落盘的话，设环境变量 `DEEPSEEK_API_KEY`，它的优先级高于设置里存的值。

### 3. 在图上画圈（画面标注）

参考图槽悬停出现铅笔图标，点开标注编辑器：

- 工具：**圈选 / 画笔 / 方框 / 箭头**
- 7 种颜色，3 档粗细，支持撤销（Ctrl+Z）与清空
- 标记**直接画进图片**，不是另存一层矢量数据 —— 送进模型的就是你眼睛看到的同一张图
- 每笔先描一层半透明黑边再画彩色线，亮背景暗背景上都看得清
- 应用后图槽显示带标记的那张，角标「已标注」；可以一键切回原图

标注副本落在 `{输出目录}\_标注\`，保留数量在设置里调（默认 60 张，超出自动回收）。

用法上，**标记负责指位置，提示词负责说意图** —— 圈出要改的地方，
然后在提示词里写清要改成什么。

## 隐私空间

加密存储。侧栏「隐私空间」进去设置密码即可启用。

### 加密方式

| 环节 | 做法 |
|---|---|
| 密钥派生 | PBKDF2-HMAC-SHA256（200,000 次哈希迭代），各安全空间独立随机盐 |
| 文件加密 | 工业级 AES-256-GCM，每项资产独立 12 字节随机 Nonce，格式 `[12 字节 Nonce][密文 + GCM 认证标签]` |
| 索引加密 | 空间索引元数据完全密文存储，隐藏资产数量、文件名及原始属性 |
| 密钥驻留 | 派生密钥仅在运行时会话内存中驻留，进程终止或手动锁定即刻销毁 |

**安全警告：系统不提供密码重置或找回途径。** 主密码与密钥不进行持久化存储，若密码遗失，已加密资产将处于不可逆的永久锁定状态。

### 安全入口与隐蔽访问

空间启用后，系统将依据隐私保护策略**自动隐蔽所有关联界面元素**：

- 侧栏功能入口自动隐藏
- 系统设置中的隐私空间管理卡片同步隐藏
- 生成历史与预览中的「移入隐私空间」操作项自动隐藏
- 版本号区域不设置提示或焦点动效

安全验证访问途径：

> **系统设置 → 底部版本标识 → 连续点击版本号 5 次**

系统将在 1.6 秒内检测到连续点击时唤起主密码验证对话框。验证通过后空间在当前会话保持解锁，可随时执行手动锁定。

### 资产归档与解密导出

- **加密归档**：执行加密封存后，系统自动抹除输出目录中的原始明文文件，并同步清除历史记录索引，确保存储介质无明文残留。
- **解密导出**：选定资产将解密导出至 `{输出目录}\隐私空间移出\`，并自动恢复历史索引。
- 归档入口：图片大图预览的操作栏，或生成历史项中的安全归档操作。

### 在隐私空间里看图

网格里是**解密后的缩略图**，点开看大图可以翻页（← →）。整个过程：

1. Rust 侧读取密文 → 用内存里的密钥解密 → 缩放到需要的大小 → 编码成 base64 传给界面
2. **全程不写明文到磁盘**，解密结果只在内存里缓存，锁定即清空

还能另存为、批量移出、批量删除、改密码（会用新盐重新加密整个库）、停用
（要求先清空，避免误删）。

## 核心用法

### 文生图

写完整句子，不要堆关键词 —— Qwen 是按语义理解的。

> 一位穿青色旗袍的年轻女子站在雨后的青石巷口，侧身回望，暖黄灯笼映在她脸上，胶片质感

Z-Image Turbo 快得多，适合先试构图和提示词，定下来再切 Qwen 精修。

### 单图编辑

公式：**改什么 + 改成什么 + 什么保持不变**

> 把她的衣服换成白色旗袍，人物和场景保持不变

「保持…不变」这句不能省，否则模型会顺手改掉别的地方。
输出尺寸自动跟随原图比例，不用手填。

### 多参考图

用 `<image1>` `<image2>` 引用对应位置的参考图：

> 保持`<image1>`的人物与姿势，穿上`<image2>`的服装，背景换成`<image3>`的雪夜街道

**输出尺寸跟随参考图 1 的比例** —— 想竖构图就把竖图放第一位。

### 帧生视频

选择一张首帧，再描述人物动作、镜头运动和声音；也可以增加尾帧，让画面逐渐过渡到指定结尾。
内置横屏、竖屏、方形三种画幅，以及约 5 / 10 / 15 秒三档时长，统一按 24 帧/秒输出。
生成完全使用本机 MiniMax H3 Turbo 模型，不调用云端接口。图片会按所选画幅居中裁切，选择接近原图的比例能减少裁切。

### 备用图库

侧栏「备用图库」是所有页面共享的图片仓库：

- **导入**：把外部图片复制到 `{输出目录}\_导入\`，之后不会再被随手清理
- **加入**：生成结果可以在结果面板点「全部加入图库」，或在预览里单张加入
- **使用**：任何页面的图槽都支持点击 → 从图库选，或直接把图拖到槽位上

图库只记录文件位置，不重复复制文件（外部导入的除外）。

## 界面要点

- **图槽**：空槽直接给「选文件 / 从图库选」两个入口，也可以拖拽落图；
  已填图时悬停出现「标注 / 图库 / 换图 / 清空」按钮
- **结果图**：点击看大图，悬停出现「2K / 编辑」按钮，一键把这张图送去别的页面继续加工
- **历史记录**：「参数复现」把当时的提示词和参数填回表单；「用作参考图」把结果填进参考图槽
- **进度**：走 ComfyUI 的 WebSocket，显示当前阶段（加载模型 → 理解提示词 → 采样生成 → 解码 → 保存）和采样步数
- **日志**：顶栏的终端图标，后端 stdout/stderr 都在里面

## 图标

图标源文件是 `src-tauri/icons/icon.svg`，构思是「**一笔画成的八角窗**」：

- 八角窗是中式建筑里框住一方天地的元素，对应「境」
- 窗框本身就是那个「画」—— 三段粗细不同，表现运笔的压力变化
- 底边左侧留了缺口，毛笔的笔锋正落在缺口上收笔
- 笔锋两侧曲线在锋尖共用同一个控制点，切线合流成锐利的锋

改图标后要重新生成全套尺寸：

```bash
# 1. 把 SVG 渲染成 1024×1024 PNG（用系统自带的 Edge 无头模式）
#    渲染时背景要透明，--default-background-color=00000000
# 2. 生成全套尺寸
cd G:\huajing
pnpm exec tauri icon src-tauri/icons/icon-source.png
```

界面里侧栏的标记用的是同一个图形的内联 SVG（`src/components/Logo.vue`），
改图标时两边要一起改。

**换图标有两个坑，都踩过：**

**① `tauri-build` 不监视图标文件。** 它只声明了对 `tauri.conf.json` 和 `capabilities`
的依赖，换了 `icons/` 里的东西它不会重新编译 Windows 资源 —— **exe 会一直带着旧图标，
而且全程没有任何报错**，只有把 exe 里的图标抠出来比对才看得出来。
`build.rs` 里补了一句 `cargo:rerun-if-changed=icons` 来堵这个洞。

**② 安装包（NSIS）默认不用应用图标。** 不显式指定的话它会用 NSIS 自带的默认图标，
所以在 `tauri.conf.json` 里写了 `bundle.windows.nsis.installerIcon = "icons/icon.ico"`。

验图标别靠肉眼看快捷方式（Windows 有图标缓存），直接抠：

```powershell
Add-Type -AssemblyName System.Drawing
[System.Drawing.Icon]::ExtractAssociatedIcon('...\huajing.exe').ToBitmap().Save('out.png')
```

### 界面验证

标注画布需要真的拖鼠标才能验，而 Tauri 的 WebView2 不暴露给 UI 自动化。
做法是在浏览器里跑：给 Tauri API 装一层桩，整个前端就能在普通浏览器中运行，
再用浏览器自动化点开标注器、真画几笔、数画布上的红色像素。

这套脚手架是临时的（`dev/browser.html` + `dev/browser.ts`），验完即删，不参与打包。
需要时按同样的思路重建即可。

它抓出过两个真 bug：

**1. 椭圆工具静默丢弃垂直/水平拖拽。**
近乎垂直或水平的拖拽会算出 0 半径，标记被直接丢掉，用户拖完一片空白只会以为工具坏了。
现在半径夹到至少半个线宽，这种拖拽会画出一条可见的线。

**2. 新生成的结果在面板里先显示空白。**
`image_infos` 是异步的（要给新图解码、生成缩略图，2K 图要好几秒），在那个窗口期里
`infos[p]` 还是 undefined，`thumbUrl` 返回空字符串 —— **浏览器对 `src=""` 的处理是清空图片**，
于是面板先是一片空白再跳一下。用户看到的就成了「点完生成，结果面板没变成新图」。

修法是给 `thumbUrl(info, fallbackPath)` 加兜底：信息没到时直接用原图路径，
新图立刻就能通过 asset 协议显示出来。同时把结果面板的 `loading="lazy"` 去掉
（刚生成出来的图必须立刻加载），并在结果变化时先清掉旧信息、给异步 watcher 加异常保护。

同一个模式在 `HistoryView`、`LibraryView`、`LibraryPicker`、`ImageSlot`、`ParamForm` 的标签 chip
里都有，一并修了。隐私空间的缩略图解密失败原本会永远转圈，现在会明确显示「解密失败」。

**3. 标注副本被清掉后，图槽误报原图丢失。**
标注是**派生副本**，落在 `{输出目录}\_标注\`，而那个目录有保留数量上限（默认 60 张，超出自动回收）。
标注文件被清掉之后，`displayPath`（标注优先）指向一个不存在的文件，于是图槽报
「文件已丢失」—— 可原图明明好好的。更糟的是生成时会把那个不存在的路径传给 ComfyUI，
在上传阶段报一句很难懂的错。

现在分两种情况处理：

| 情况 | 图槽 | 生成按钮 |
|---|---|---|
| 只有标注副本丢了、原图还在 | 退回原图正常显示，并自动清掉失效的标注 | 可用 |
| 原图也真的不在磁盘上 | 「文件已丢失，点此重选」 | **禁用**，提示「原图 的文件已不在磁盘上，请重新选择」 |

顺手加了一道生成前拦截：任何「填了但文件不在磁盘上」的参考图都会在点生成之前被拦住，
而不是等到上传阶段才失败。

**4. 竖图在预览里被切掉。**
预览区原本是 `display: grid; place-items: center`，**隐式行高是 `auto`（由内容决定）**，
此时图片的 `max-height: 100%` 会因为"百分比相对不确定高度"被当成 `none` —— 等于没约束。
结果 768×1376 的竖图按原始尺寸渲染，下半截被窗口切掉，全屏也看不全。

改成 flex 容器（高度确定，百分比才生效），并用 `margin: auto` 而不是
`justify-content: center` 居中 —— 后者在内容溢出时会把左上角顶出可视区且滚动不到。
标注画布是同一个写法，只是被 `overflow: hidden` 掩盖了，一并改了。

顺带加了「**适应窗口 / 1:1**」切换（快捷键 `F` 或 `0`）：适应窗口看整体，
1:1 按原尺寸显示、可滚动看细节 —— 2K 图适应窗口后只有三分之一大，判断画质时需要原尺寸。
隐私空间的查看器共用同一套样式，一起受益。

### 四个必须知道的坑

**1. 必须用 MSVC 工具链**

默认的 `stable-x86_64-pc-windows-gnu` 会去 PATH 里找 `x86_64-w64-mingw32-gcc`，
而 PATH 最前面是 `E:\Dev-Cpp\MinGW64`（gcc 4.9.2），它的 `ld` 不认识 rustc 1.98
传的 `--high-entropy-va`，链接必然失败。已在 `src-tauri\rust-toolchain.toml`
里固定成 MSVC，不要删那个文件。

**2. ComfyUI 的输出必须是文件重定向，绝不能用管道**

这条是踩过坑的，改动前务必读完。

应用原先用 `Stdio::piped()` 接管 ComfyUI 的 stdout/stderr，再起任务读出来推给日志面板。
问题是：**管道是父子进程之间的私有通道，读端随父进程消失就没了**。
应用一退出（哪怕是崩了、被任务管理器杀了），它启动的 ComfyUI 就成了孤儿，
stdout/stderr 指向已死的管道。此时：

- ComfyUI **表面完全正常** —— 端口在听、能建队列、能加载模型
- 但 tqdm 每次建进度条都要 `sys.stderr.flush()`，于是 KSampler 一进去就抛
  `OSError: [Errno 22] Invalid argument`
- 结果是**每一次生成都失败**，而错误信息完全指不到真正的原因

现在改成重定向到 `{ComfyUI 根目录}\huajing_console.log`（见 `open_console_log`）。
文件与父进程生死无关，应用退出后 ComfyUI 照常工作；日志面板改成跟随这个文件读
（`spawn_log_tailer`），应用重启后也能从文件里读回历史日志。

`tests/console_log.rs` 把这件事钉住了，其中
`child_keeps_writing_after_parent_lets_go` 就是模拟「父进程放手后子进程还能不能写」。

**3. 改工作流图要核对参数名**

`src/api/graphs.ts` 里所有节点输入名都是按 ComfyUI 源码的 `INPUT_TYPES` 核对过的。
改名之前先查源码，写错的话 ComfyUI 会在 `/prompt` 阶段直接返回参数校验失败。

尤其注意 autogrow 输入的名字格式是 `组名.模板名`（例如 `images.image_1`，1 起数），
漏掉前缀是常见错误。

**4. 构建前先关掉正在运行的画境**

Windows 会锁住正在运行的 exe，`tauri build` 会以
`failed to remove file ... os error 5` 失败。先关掉应用再构建。
